| `BOOTSTRAP_SECRET` | Cloudflare のシークレット | 承認済みデバイスが 0 台のときだけ、最初のデバイスを承認できる |
| Cloudflare アカウント・`wrangler login` の認証情報 | Cloudflare / 開発 PC | **すべてのデータとアプリを自由に操作できる（最も重要）** |

## 3. 脅威モデル

### 信頼境界

```
[インターネット] ──HTTPS──> [Worker] ──バインディング──> [D1 / R2]
      ▲                         ▲
  ブラウザ（承認済みデバイス）   [Cloudflare アカウント]（ダッシュボード・wrangler）
```

- ブラウザから届くものはすべて信用しない（Cookie・ヘッダー・本文・ファイル名・画像の中身）
- 画面のファイル（HTML / JS / CSS）は誰でも取得できる。データは必ず Worker のチェックを通る
- Cloudflare アカウントはアプリの認証の外側にある（アカウントを守るのは 2FA）

### 想定する攻撃者と対策の要点

| 攻撃者 | できること | 主な対策 |
| --- | --- | --- |
| インターネット上の誰か | 登録画面へのアクセス、総当たり、大量アクセス | デバイス承認 + パスキー、ブートストラップの制限、承認待ち数の上限、Cloudflare Access（推奨） |
| 悪意のあるサイト | ログイン中のブラウザに勝手にリクエストを送らせる（CSRF）、iframe に埋め込む | `SameSite=Strict`、`x-mdv` ヘッダー必須、`frame-ancestors 'none'` |
| Cookie を盗んだ人 | なりすまし | セッションの期限（操作なし 14 日・絶対 90 日）、重要な操作の前の本人確認、デバイス・パスキーの削除で即無効 |
| 端末を拾った人 | ロックされていなければブラウザを操作できる。端末に残したノートのキャッシュ・下書きを読める | 重要な操作の前の本人確認、別の端末からデバイスを削除、ログアウトでキャッシュ・下書きを消す、特に秘密にしたいノートは暗号化 |
| Cloudflare 側（事故・開示請求など） | 保存されたデータを読める | 特に秘密にしたいノートはブラウザで暗号化（サーバーには暗号文だけ） |
| 悪意のある内容（取り込んだノートや画像） | XSS、偽装ファイル | Markdown を DOMPurify で無害化、CSP、画像形式を中身で判定、SVG を拒否 |
| 依存パッケージの侵害 | 悪意のあるコードの混入 | 依存を最小限にする、`package-lock.json`、`npm audit`、CI |
| Cloudflare アカウントの乗っ取り | すべて | 2FA、API トークンを最小権限で発行（アプリの範囲外） |

## 4. 権限表

主体（利用者の状態）ごとに、どの API を使えるかの一覧です。`tests/authz.test.ts` の `ENDPOINTS` と一致させています。
API を追加・変更したら、この表とテストの両方を更新してください。

| 主体 | 説明 |
| --- | --- |
| 匿名 | Cookie なし、または不明な Cookie |
| 承認待ち | 登録したが未承認のデバイス |
| 承認済み | 承認済みデバイスだが、パスキーでログインしていない |
| ログイン中 | 承認済みデバイス + パスキーでログイン済み（セッション有効） |

| API | 匿名 | 承認待ち | 承認済み | ログイン中 |
| --- | :-: | :-: | :-: | :-: |
| `GET /api/device`、`POST /api/device/register` | ✅ | ✅ | ✅ | ✅ |
| `POST /api/device/bootstrap` | ✅ ※1 | ✅ ※1 | ✅ ※1 | ✅ ※1 |
| `POST /api/passkey/login/*`、`POST /api/logout` | ❌ | ❌ | ✅ | ✅ |
| `POST /api/passkey/register/*` | ❌ | ❌ | ※2 | ✅ ※3 |
| ノート・フォルダ・履歴・リンク・タグ・検索・画像・取り込み・書き出し・バックアップの API | ❌ | ❌ | ❌ | ✅ |
| `GET /api/devices`、`GET /api/passkeys` | ❌ | ❌ | ❌ | ✅ |
| `POST /api/devices/approve`、`DELETE /api/devices`、`DELETE /api/passkeys` | ❌ | ❌ | ❌ | ✅ ※3 |

- ※1 Cookie で登録済みのデバイスが必要。承認済みデバイスが 1 台もないときだけ成功する
- ※2 パスキーが 0 個のとき（初回・リセット後）だけ
- ※3 最後にパスキーで本人確認してから `REAUTH_WINDOW_MINUTES`（既定 5 分）以内のみ。過ぎていれば `403 reauth_required` を返し、画面がパスキーでの確認を求める
- ❌ はすべて `401`。GET 以外は、権限があっても `x-mdv: 1` ヘッダーがなければ `403`

## 5. 対策の一覧

OWASP API Security Top 10 2023 の分類に沿って、このアプリでの対応をまとめます。

| 分類 | このアプリでの対応 | 確認方法 |
| --- | --- | --- |
| API1 オブジェクト単位の認可（BOLA） | 利用者が 1 人なので所有者の区別はない。すべてのデータ API はログイン中のみ | 権限表のテスト |
| API2 認証の不備 | デバイス承認 + パスキー（本人確認必須）。トークンは 256 ビットの乱数で、サーバーにはハッシュだけを保存。ログインのたびに新しいセッションを発行。操作なし 14 日・絶対 90 日で失効。ブートストラップは 0 台のときだけ・失敗回数で 1 時間ロック・同時実行でも 1 台だけ | `tests/authz.test.ts`（セッション・ブートストラップ） |
| API3 プロパティ単位の認可（BOPLA） | 各 API は必要な項目だけを受け取り、DB の列を直接更新させない。応答にトークンやハッシュを含めない | コードレビュー |
| API4 リソースの過剰消費 | ノートの最大文字数、画像の最大サイズ、リンク数・タグ数・履歴数の上限、承認待ちデバイス数の上限、取り込み・フォルダ操作 1 回あたりのノート数の上限、バックアップの保持日数。zip・画像の縮小・暗号化はブラウザで行う。大量アクセスは Cloudflare Access / レート制限ルールで防ぐ（推奨） | `tests/authz.test.ts`・`tests/notes.test.ts` |
| API5 機能単位の認可（BFLA） | デバイスの承認・削除、パスキーの追加・削除は、ログイン中かつ最近の本人確認が必要 | 権限表・reauth のテスト |
| API6 業務フローの悪用 | 承認待ちデバイスにはペアリングコードの照合が必要。期限切れは承認できない。最後のパスキーは削除できない。上書き・削除・リンクの書き換え・取り込み・復元の前の内容は履歴に残す | `tests/authz.test.ts`・`tests/notes.test.ts` |
| API7 SSRF | Worker から外部 URL を取得しない | 対象外 |
| API8 設定の不備 | CSP・`nosniff`・`Referrer-Policy`・HSTS・`frame-ancestors 'none'`、API は `Cache-Control: no-store`。Cookie は `__Host-`・`HttpOnly`・`Secure`・`SameSite=Strict`。エラー応答に内部情報を含めない | レスポンスヘッダーのテスト |
| API9 API の棚卸し | API の一覧は README と権限表で管理。未知のパスは 401 / 404 | 権限表のテスト |
| API10 外部 API の安全でない利用 | 外部 API を使わない | 対象外 |

Web フロントエンド固有の対策:

- **XSS**: Markdown は marked で HTML にしたあと、必ず DOMPurify で無害化してから表示する。それ以外の利用者由来の文字列（ノート名・デバイス名・検索結果など）は `textContent` で表示する。`innerHTML` に入れてよいのは DOMPurify の出力と固定文字列だけ
- **CSP**: 静的ファイルは `script-src 'self'`・`style-src 'self'`（外部・インラインのスクリプトとスタイル不可）。外部の画像（`https:`）は表示できる。
  エディタ（CodeMirror）は Shadow DOM の中に置き、CSP を緩めずに動かしている（`'unsafe-inline'` は使わない）。E2E テストで CSP 違反が出ないことを確認している
- **画像**: 形式はファイル先頭のバイト列で判定（PNG / JPEG / GIF / WebP / AVIF のみ）。SVG は受け付けない。応答には `nosniff` と `sandbox` 付き CSP
- **秘密情報**: ブラウザの JavaScript から読めるストレージ（localStorage）に秘密情報（トークン・パスフレーズ・鍵）を入れない。Cookie は `HttpOnly`。
  オフライン中の下書きは localStorage に入るが、暗号化したノートは暗号文のまま入れる
- **端末に残すデータ**: Service Worker はノートなど読み取り API の応答をキャッシュする（オフラインで読むため）。ログアウトしたとき・ログインが切れたとき（401）に消す
- **ノートの暗号化**: AES-GCM（256 ビット）、鍵はパスフレーズから PBKDF2-SHA256（既定 60 万回）で作る。ノートごとに別の salt、保存のたびに別の IV。パスフレーズはタブを開いている間だけメモリに置く。暗号化するときに、暗号化前の内容が残った履歴を消せる
- **取り込み**: zip はブラウザで展開する。`.obsidian` などの隠しフォルダと、ノート・画像以外のファイルは取り込まない。パスはサーバーで検証する（`..` などを拒否）

## 7. 動的検査（実際にリクエストを送る検査）の安全境界

- 対象は **ローカルの `wrangler dev`（`localhost`）と `npm test`・`npm run test:e2e`（専用のデータ `.wrangler/e2e/`）だけ**。本番（`*.workers.dev` や独自ドメイン）には、攻撃を模したリクエスト・スキャナー・負荷試験を送らない
- テストデータだけを使う。本物のノート・パスキー・Cookie を検査に使わない
- OWASP ZAP などのスキャナーを使う場合は、人が明示的に承認し、ローカル環境に限定し、外部への通信を遮断した状態で行う。スキャナーはリダイレクトや別ドメインへ勝手にアクセスすることがあるので、アプリ側の URL チェックだけに頼らない
- データの削除・設定の弱体化（CSP を外す、認証を切るなど）を検査のために行わない

## 8. 既知の残存リスク

対応しないことにしたもの、または現時点で対応できないものです。

| リスク | 影響 | 理由・緩和策 |
| --- | --- | --- |
| 登録画面は誰でも開ける | 承認待ちの枠を埋められる、無料枠のリクエスト数を使われる | Cloudflare Access の有効化を推奨（`docs/cloudflare.md`） |
| Cookie を盗まれると期限までなりすませる | ノートの閲覧・改ざん | 期限の短縮（`SESSION_IDLE_TIMEOUT_DAYS` など）、重要な操作は本人確認、気づいたらデバイスを削除 |
| 暗号化していないノートは Cloudflare から読める | Cloudflare 側の事故・開示請求 | 特に秘密にしたいノートは、ノートごとの暗号化（🔒）を使う。すべてを暗号化すると検索・リンクが使えなくなるため、既定では暗号化しない |
| 暗号化の限界 | 暗号化する前の自動バックアップ・書き出した zip・（消さなかった場合の）履歴には暗号化前の内容が残る。ノート名（パス）は暗号化しない。画面のコードが改ざんされるとパスフレーズを盗まれうる | 暗号化するときに案内を出す。画面のコードは同じサーバーから配信され、CSP で外部スクリプトを禁止している |
| 端末に残したノート | 端末を使える人に、一度開いたノート・未送信の下書きを読まれる | ログアウトで消える。端末をなくしたら別の端末からデバイスを削除する（次に開いたとき 401 になりキャッシュが消える） |
| ノートが非常に多いと、無料プランの CPU 時間（10ms）を超えうる | フォルダの名前変更・削除、自動バックアップが失敗する | 数百件程度までは収まる想定。1 回で扱えるノート数に上限（`MAX_NOTES_PER_BULK_OPERATION`）。必要なら有料プラン |
| 自動バックアップは同じ Cloudflare アカウントの中 | アカウントごと失うと戻せない | ときどき zip に書き出して手元にも保管する |
| 外部の画像（`https:`）をノートに書くと、表示時に外部へアクセスが発生する | 閲覧したことが外部に伝わる | 自分で書いたノートが前提。気になる場合は `_headers` の `img-src` から `https:` を外す |
| 開発用ツール（wrangler・miniflare・@cloudflare/vitest-pool-workers が使う undici・sharp・zod）に既知の脆弱性 | 本番には含まれない。ローカル開発・テスト時のみ | 2026-10-30 時点で最新版でも未修正（npm audit が示す「修正」は古い版への戻し）。Dependabot の更新で再確認 |
| 使用中かどうかの画像の判定はファイル名の部分一致 | 未使用の画像を使用中と表示することがある | 削除時に確認ダイアログを出している |

## 9. 変更するときのチェックリスト

- [ ] API を追加・変更した → `src/index.ts` などの**正しい権限のブロック**に置いたか。権限表と `tests/authz.test.ts` の `ENDPOINTS` を更新したか
- [ ] データを変更する API → GET 以外のメソッドにしたか（`x-mdv` ヘッダーのチェックが効く）
- [ ] デバイス・パスキー・セッションを変える操作 → `requireRecentAuth` を呼んだか
- [ ] SQL → 値は必ず `bind()` で渡したか（文字列の連結で SQL を組み立てない）
- [ ] 利用者由来の文字列を画面に出す → `textContent`（`client/util.js` の `el()`）か DOMPurify を通したか
- [ ] 画面の変更 → CSP（`style-src 'self'` など）を緩めずに動くか。`npm run test:e2e` で CSP 違反が出ないか
- [ ] 端末に保存するもの（localStorage・Cache Storage） → 秘密情報（トークン・パスフレーズ・鍵）を入れていないか。ログアウトで消えるか
- [ ] ノートの内容を扱う新しい処理 → 暗号化したノート（`%%mdvault-encrypted v1%%` で始まる）の暗号文を壊したり、平文を送ったりしないか
- [ ] 利用者がアップロードしたものを返す → `content-type` をサーバーで決め、`nosniff` と `sandbox` を付けたか
- [ ] 設定値 → `wrangler.jsonc` の `vars`。秘密情報 → `wrangler secret put`（Git に入れない）
- [ ] Cookie → `setCookie()` を使ったか
- [ ] 依存パッケージを追加した → 本当に必要か、メンテナンスされているか、`npm run audit` が通るか
- [ ] `npx tsc`・`npm test`・`npm run test:e2e` が通るか

## 10. レビュー報告の書式

レビューの結果は `docs/security-review/YYYY-MM-DD.md` に、次の形で残します。
スキャナーの生の出力は秘密情報や個人情報を含むことがあるので、`security-reports/`（Git 管理外）に置き、報告書には要約だけを書きます。

```markdown
# セキュリティレビュー YYYY-MM-DD

- 対象: コミット <SHA>、範囲（例: 画像の添付機能の差分）
- 実施した検査: コマンドとツールのバージョン、結果
- 実施していない検査: 理由

## 指摘

### <番号>. <タイトル>
- 重大度: Critical / High / Medium / Low / Info
- 確信度: 確認済み（テストで再現） / 可能性あり（コード上の根拠のみ）
- 根拠: ファイル・行・設定項目・テスト結果
- 影響:
- 再現方法: 破壊的でない手順（テストコードなど）
- 対策: 実施済みならコミット・テスト名
```
