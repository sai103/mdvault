## 指摘

### 1. セッションを盗まれると、自分のパスキーを追加されて居座られる
- 重大度: Medium
- 確信度: 確認済み（コード上、ログイン中なら追加の確認なしにパスキー登録・デバイス承認ができた）
- 根拠: `src/passkey.ts` の `requireSessionOrNoPasskeys`、`src/index.ts` の `POST /api/devices/approve`
- 影響: Cookie を盗んだ人が、自分の認証器をパスキーとして登録したり、自分のデバイスを承認したりすると、元のセッションを消しても入り続けられる
- 対策: デバイスの承認・削除、パスキーの追加・削除の前に、最近（既定 5 分以内）のパスキーでの本人確認を必須にした（`requireRecentAuth`、`REAUTH_WINDOW_MINUTES`）。ログインのたびにセッショントークンを発行し直すようにした。テスト: 「本人確認のし直し（reauth）」

### 2. セッションに絶対的な期限がない
- 重大度: Low
- 確信度: 確認済み
- 根拠: `src/passkey.ts` の `currentSession`（使うたびに期限を延長するだけだった）
- 影響: 盗まれたセッションを使い続ければ、いつまでも有効
- 対策: ログインから `SESSION_ABSOLUTE_TIMEOUT_DAYS`（既定 90 日）で失効させた。テスト: 「使い続けていても、絶対期限を過ぎたセッションは無効」

### 3. ブートストラップを同時に実行すると 2 台とも承認される
- 重大度: Low
- 確信度: 可能性あり（コード上の根拠のみ。確認と更新が別の SQL だった）
- 根拠: `src/index.ts` の `bootstrap`
- 影響: 正しいシークレットを知っている人が 2 台を同時に承認させられる（シークレットが必要なので影響は小さい）
- 対策: 「承認済みが 0 台」の確認と承認を 1 つの SQL にした。テスト: 「承認済みデバイスが 0 台なら使え、2 台目は通らない」

### 4. 期限切れの承認待ちデバイスを承認できる
- 重大度: Low
- 確信度: 確認済み
- 根拠: `src/index.ts` の `POST /api/devices/approve`（期限切れの削除は新規登録のときだけだった）
- 影響: 24 時間以上前に誰かが登録したデバイスを、誤って承認する可能性
- 対策: 承認時に `PENDING_DEVICE_TTL_HOURS` 以内かを確認するようにした。テスト: 「期限切れの承認待ちデバイスは承認できない」

### 5. Cookie に `__Host-` が付いていない
- 重大度: Low
- 確信度: 確認済み
- 根拠: `src/common.ts` の `setCookie`
- 影響: 独自ドメインで使う場合、同じドメインの他のサブドメインから Cookie を上書きされる可能性（workers.dev では起きない）
- 対策: HTTPS では `__Host-mdv_device` / `__Host-mdv_session` にした。テスト: 「Cookie は __Host- 付き・HttpOnly・Secure・SameSite=Strict」
- 注意: Cookie 名が変わるので、**既存の環境では全デバイスで登録・承認からやり直しになる**

### 6. HSTS ヘッダーがない
- 重大度: Info
- 確信度: 確認済み
- 根拠: `public/_headers`、`src/common.ts` の `SECURITY_HEADERS`
- 影響: 独自ドメインで、初回に HTTP でアクセスしたときに盗聴・改ざんされる余地（`.dev` ドメインはブラウザ側で HTTPS 強制のため workers.dev では影響なし）
- 対策: `Strict-Transport-Security: max-age=31536000` を付けた（`includeSubDomains` は他のサブドメインへの影響を避けるため付けない）

### 7. 開発用ツールの依存に既知の脆弱性
- 重大度: Low（本番には含まれない）
- 確信度: 確認済み（`npm audit`）
- 根拠: wrangler 4.152.0 → miniflare → undici 7.29.1
- 対策: 最新版でも未修正のため、残存リスクとして記録。wrangler を更新したときに再確認する
