# テストシナリオ

使いかたマニュアル（[manual.md](manual.md)）の章ごとに、どの自動テストで確かめているかをまとめた一覧です。
自動テストは、GitHub に push したとき・プルリクエストを作ったときに CI（`.github/workflows/ci.yml`）で毎回実行されます（CI のしくみは [ci.md](ci.md)）。

## テストの種類

| 種類 | ファイル | 実行方法 | 内容 |
| --- | --- | --- | --- |
| Worker のテスト | `tests/authz.test.ts`、`tests/notes.test.ts` | `npm test` | API を直接呼ぶ。認可・CSRF・セッション・入力の検証・リンクの書き換え・検索・バックアップなど |
| E2E（主要機能） | `e2e/app.spec.js` | `npm run test:e2e` | ブラウザで操作する。主要な機能と、XSS・CSP 違反・オフライン・ログアウト時のキャッシュ削除 |
| E2E（シナリオ） | `e2e/scenarios.spec.js` | `npm run test:e2e` | マニュアルの手順どおりに操作する。テスト名の【n章】がマニュアルの章 |

- E2E の 2 つのファイルは、別々のテスト用サーバー（ポート 8788・8789、データは `.wrangler/e2e-<ポート>/`）で、それぞれ「最初の 1 台」の登録から始めます
- パスキーは Chromium の仮想認証器で代用します。2 台目のデバイスでは、1 台目のパスキーを写して「同期されたパスキー」の代わりにします
- 本人確認のし直しを確かめるため、テスト用サーバーでは本人確認の有効時間を 3 秒にしています
- どの E2E テストも、最後に「ページのエラーと CSP 違反が 1 件もないこと」を確認します

## 自動テストでは確かめていないこと

次のことは、自動テストの環境では再現できないため、リリースの前や大きな変更の後に手で確認します。

| 確認すること | 手順の参考 |
| --- | --- |
| 実機のパスキー（Windows Hello・Touch ID・Face ID・Android・USB セキュリティキー）での登録とログイン | マニュアル 2・3・19 章 |
| QR コードで別の端末のパスキーを使うログイン | マニュアル 3 章 |
| Safari・Firefox での表示と操作（E2E は Chromium だけ） | マニュアル全体 |
| スマートフォンの画面幅での操作（サイドバーの引き出し） | マニュアル 4 章 |
| ホーム画面への追加（PWA のインストール） | マニュアル 17 章 |
| 本番環境（Cloudflare）での動作と CPU 時間の制限、毎日の自動バックアップが実際に動くこと | [deploy.md](deploy.md)、[cloudflare.md](cloudflare.md) |
| 写真の位置情報（EXIF）が取り除かれること | マニュアル 12 章。位置情報付きの写真を添付し、ダウンロードした画像に残っていないことを確かめる |

## テストを追加するとき

- マニュアルに手順を書き足したら、`e2e/scenarios.spec.js` に【章】付きのテストを追加し、この表を更新します
- API や権限を変えたら、`tests/authz.test.ts` の権限表も更新します（[security.md](security.md)）
- `e2e/scenarios.spec.js` のテストは上から順に同じデータを使います。前のテストで作ったノートに頼る場合は、テストの中にそのことを書きます
